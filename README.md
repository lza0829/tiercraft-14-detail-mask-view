# 05-tiercraft（筑层）

筑层 — 数仓分层建设台：贴源入仓 → 明细清洗标准化 → 汇总落表 → 层间行数/键对账。

**不是** 多源 Feed 归并，**不是** 作业依赖编排，**不是** CDC 变更流按序落库，**不是** 质检隔离签发。
**也不是** 报表看板 / CRUD 后台 / 电商订单前台 / OA 工单。

## 启动

```bash
docker compose up --build
```

本地开发：

```bash
# 后端
cd backend
pip install -r requirements.txt
set DATA_DIR=..\data
uvicorn app.main:app --reload --port 10500

# 前端
cd frontend
npm install
npm run dev
```

| 入口 | 地址 |
| --- | --- |
| 前端 | http://localhost:5500 |
| 接口 | http://localhost:10500 |

## 主链

登记主题域 → 贴源层装载夹具 → 明细层清洗标准化 → 汇总层聚合 → 层间对账报告与各层列表数字同源

脱敏外链：启用一版脱敏规则（店名保留首尾、中间掩码）→ 按「规则版本+批次」生成脱敏快照 → 失败闭导出正式文件 → 导出记录同源登记。

## 脱敏与导出约定

- **规则版本化**：脱敏规则只增不改，可启用任一版本；新建/切换启用版本只影响之后新生成的快照与导出，历史快照与历史导出绝不改写。
- **物理隔离（择一已选）**：脱敏结果固化在独立脱敏快照表 `mask_snapshot_rows`（按规则版本+批次成行），与明文明细物理隔离；不用「当前规则」对历史批次做读时临时遮罩冒充旧快照。
- **失败闭导出（择一已选）**：先写临时目录，抽样校验通过后原子改名落正式文件；抽样检出明文店名则整次失败——不落正式文件、不写成功导出记录（只写失败记录）。
- **原文红线**：贴源层、明细原表、分层任务与层间对账一律基于原文；生成快照与导出只读明细原表、绝不回写。内部只读脱敏视图 `v_detail_masked` 仅供查看，不作为对账或分层任务的数据源。
- **同源登记**：导出记录含规则版本、成败、失败原因、快照行数，均与本趟批次的明文明细行数同源派生。

## 界面约定

页面文案全部中文；分层称「贴源层 / 明细层 / 汇总层」，界面不出现英文缩写站名。
入口：「脱敏规则」页维护规则版本，「快照导出」页生成快照、预览脱敏行并导出正式文件。
